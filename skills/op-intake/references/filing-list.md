# 起票前の一覧

手順 4 で人に見せる一覧。Project ではこれと各 Issue の本文全文を 1 つのファイルに書く。

## 一覧の前に書くこと

- 重複の結果: `op scan dedup` の判定 (下書きごとに pass / 既存 #N と重複 / 類似 #N / 下書きどうしで重複)。
- 関係する open Issue: 重なりではないが同じところを触るもの (手順 3 の 3)。
- 新しく作るラベル (無ければ「なし」)。
- 起票の順 (依存先が先)。

## 一覧の表

```markdown
| key | title | expert | post-check | 大きさ | depends_on | 鎖 | スレッド | スレッド内で並べる組 |
|---|---|---|---|---|---|---|---|---|
```

- 大きさ・depends_on: 本文の `## 振り分けの材料` と同じ値。
- 鎖: その下書きに至る `op-depends-on` の並び。依存先から `A → B → D` の形で書き、依存先が 2 つあれば `A → {B, C} → D`。依存の無い下書きは自分 1 件。
- スレッド (案): 依存も触るファイル・画面の重なりも無いものは別のスレッドにする。鎖の中は 1 つのスレッドが下から積み重ねる。枝分かれした鎖は、枝どうしで触るファイルが重ならなければ枝ごとに別のスレッドにしてよい (根の PR の上に積む)。依存先が 2 つ以上ある下書きは、依存先のどちらかのスレッドに入れる。Project ではコーディネーターの決まりが優先する。
- スレッド内で並べる組: 同じスレッドの中で、互いに依存せず触るファイルが重ならない下書きの組。進める順に `{B, C} → {D}` の形で書く。組は一覧にだけ書き、Issue 本文には書かない。

例:

| key | title | expert | post-check | 大きさ | depends_on | 鎖 | スレッド | スレッド内で並べる組 |
|---|---|---|---|---|---|---|---|---|
| A | … | feature | null | 大 | なし | A | 1 | {A} → {B, C} → {D} |
| B | … | feature | null | 中 | A | A → B | 1 | 同上 |
| C | … | feature | null | 大 | A | A → C | 1 | 同上 |
| D | … | feature | null | 中 | B, C | A → {B, C} → D | 1 | 同上 |
| E | … | feature | null | 中 | なし | E | 2 | {E} |
| F | … | feature | null | 中 | A | A → F | 3 (A の上に積む) | {F} → {G, H} |
| G | … | feature | null | 小 | F | A → F → G | 3 | 同上 |
| H | … | feature | null | 小 | F | A → F → H | 3 | 同上 |
